# 创建 UI 与设置材质

[指南目录](README.md) · [English](../en/ui-and-materials.md) · [日本語](../ja/ui-and-materials.md)

使用 Scene Lab 的 [HelloScene.cs](../examples/HelloScene.cs) 创建画布、深色面板与文字。Canvas 提供参考尺寸，Panel 提供背景对比，Text 提供消息，各自承担明确的职责。

## 保持文字可读

明确设置文字颜色与背景。控件支持相应状态时，分别检查普通、禁用、选中和悬停状态。悬停时清楚，不代表未选中的框或静止文字也看得清。

`UI_Text` 会异步生成贴图，改变内容或排版可能触发新一轮准备；逐帧重复设置同一个字符串不会让计数器更平滑。新内容准备期间，引擎可以继续保留旧的可绘制结果，所以“贴图存在”不代表“最新文字已就绪”。文字未更新时检查 `Is_Preparing` 与 `Last_Error`。

移动项目时保留生成的文字资源。使用目标设备具备的字体或随附回退字体，并检查实际语种的字形。提前准备基础拉丁字符，不代表日文排版与中文内容也已经准备完成。

## 揭幕前准备完整界面

地区选择页应把标题、地区按钮、当前区域说明和开始按钮，与地图一同准备。让首屏组件完成登记并保持可被准备的状态。等真实资源就绪后再显示，不要地图已经出现了才启动另一条“每帧一个文字”的队列。

Scene Lab 使用 `1280 × 720` 参考画布。测试较窄与较宽输出，检查指针命中与玩家看到的控件是否一致。转换输入坐标使用当前客户区大小，不使用编辑器子窗体代替独立游戏窗口的尺寸。

## 设置材质

将模型和纹理导入 `Resources`，把模型放到场景，再在对象详情中设置材质。网格、纹理与着色器保持项目相对路径。材质仍指向另一台电脑的绝对路径时，只复制模型不会使它自动可移植。

Blender 材质不保证在运行时自动得到相同画面。根据受支持的着色器输入重建其表面意图，对照游戏输出检查透明度、面剔除与深度写入。玻璃错误写入深度时可能挡住另一层表面，提高透明度数值不能修正这个排序问题。

检查细线锯齿时，分别判断几何边缘、纹理缩小采样与着色器生成细节。选择项目可用的抗锯齿方法，并在导出中包含需要的方法。抗锯齿不能修复缺失纹理或未受支持的材质特性。现有方法与打包约定见发布归档中的 `AntiAliasing-1.0.23.txt`。
