# 导出游戏

[指南目录](README.md) · [English](../en/exporting.md) · [日本語](../ja/exporting.md)

将 Scene Lab 导出为不依赖编辑器启动的游戏。导出使用随包提供的预编译 GameRuntime，并编译项目组件，不是在玩家设备上重新编译私有引擎源码。

## 准备与导出

1. 保存 Menu、Arena、组件绑定和项目设置，在项目配置中确认预期启动场景。
2. 确保运行包能够访问两个场景，包括仅在脚本路径中出现的 Arena。核对模型、纹理、字体与着色器依赖，不能因为资源曾出现在编辑器缓存中，就认为它一定被打包。
3. 停止测试，在项目菜单打开导出，选择 Windows x64、构建配置与项目支持的图形接口。
4. 输出目录放在引擎安装目录和源项目数据目录之外。首次测试可保留调试控制台，以便读取启动错误。
5. 执行导出。目标已存在时，明确选择覆盖、另存为带后缀的副本，或取消。
6. 从导出目录运行最外层游戏 EXE，不启动编辑器，再执行 Menu → Arena 流程。

抗锯齿可以固定打包一种方法，也可以包含计划供运行时切换的受支持方法。运行时不能选择包中没有包含的方法。

## 检查可移植性

把完整导出目录复制到不同路径，不只复制 EXE。在没有编辑器进程的情况下运行，检查场景进入、音频、文字、输入与返回导航。换目录可检查路径假设，但不能代替另一台设备上的硬件测试。

独立证据查看器和编辑器测试窗口边框属于工具，不是游戏内容。游戏代码可以调用基础录制 API，但不代表编辑器的采集设置窗和资料库也会被嵌入游戏。

单独保留源项目。运行包不是可编辑源项目的备份，把新引擎安装目录覆盖到运行包上也不是游戏更新方式。

导出失败时保留首条错误与构建日志。先解决项目组件编译器或依赖缺失，不要靠把整个引擎源码目录塞进游戏包来规避问题。
