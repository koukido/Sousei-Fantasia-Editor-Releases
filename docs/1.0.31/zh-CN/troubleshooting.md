# 排查项目问题

[指南目录](README.md) · [English](../en/troubleshooting.md) · [日本語](../ja/troubleshooting.md)

从失败的操作与第一条错误开始，不要反复重载场景。把同一次运行的版本、项目路径、场景路径、操作步骤与日志放在一起。

| 现象 | 先检查 | 下一步 |
| --- | --- | --- |
| 测试无法启动，只显示构建日志路径 | 日志中的第一条编译错误。 | 修正对应文件/行或工具链，通用启动弹窗本身不能指出代码错误。 |
| 第二个编辑器拒绝打开项目 | 同一项目是否已经打开。 | 正常关闭原实例，不删除活动项目锁来强制多个写入者。 |
| Arena 一直准备中 | `State`、`Current_Work`、待处理/失败组件和 `Error`。 | 检查路径，初始化时登记完整首屏，不强制 Ready。 |
| 按 Enter 没反应 | 游戏焦点、`Can_Activate` 与本次操作票据。 | 就绪后再按一次，核对激活是否被拒绝。 |
| 层级变了但编辑器画面空白 | 相机联动、观察方向与渲染暂停。 | 分别对照游戏窗口和编辑器，检查项目的编辑器桥接。 |
| 地图先出现，文字与按钮后出现 | UI 延后登记或文字组件被禁用。 | 揭幕前准备完整首屏，不依赖未激活 Update。 |
| 已回到 Menu，但画面仍被覆盖 | 旧票据/场景实例归属、项目遮罩状态。 | 将本实例对应本操作，只清除项目自己的已结束遮罩。 |
| 录像 Failed 或只有部分视频 | `recording.json` 与 `encoder.log`。 | 保留整个运行目录，检查 FFmpeg、容量/时长、首帧等待与积压后再录。 |
| 大部分 CPU 轨道空白 | 覆盖缺口、完整档案计数与时钟对齐。 | 加载所有分段，区分预览淘汰与真实档案丢失。 |
| 游戏只在开发目录能运行 | 项目相对依赖与完整导出目录。 | 移动完整运行包，在没有编辑器时复现。 |

## 提供可处理的问题

尽量缩小到小项目，说明做了什么、预期是什么、实际出现什么。附上编辑器版本、语言、图形接口、输出大小与首条相关错误。卡顿问题提供短视频及覆盖同一时间的 CPU 区间。

分享前移除凭据、个人数据和无关文件。运行资料含游戏画面、控制信号、路径与源码名称，应由你决定是否分享；采集与查看器不会自动将其提交服务器。公开问题不要求公开私有游戏或引擎实现。

示例在新项目正常，加入某个组件后才失败时，先检查这个组件的资源与生命周期假设。最小案例也失败时，将其保留为可复现的引擎问题。按证据区分归属，不把所有可见问题都归咎项目开发者。
