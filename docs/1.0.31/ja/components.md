# コンポーネントを書く

[ガイド一覧](README.md) · [English](../en/components.md) · [简体中文](../zh-CN/components.md)

コンポーネントはシーンオブジェクトに動作を追加します。スクリプトを`Controller`に追加すると、そのオブジェクト用のインスタンスが作られます。`Resources/Scripts`にファイルを置くだけでは実行されません。

## C#のライフサイクル

`SouseiFantasia.MonoBehaviour`を継承します。[HelloSceneの例](../examples/HelloScene.cs)は`Start`で一度だけUIを作ります。

| コールバック | 用途 |
| --- | --- |
| `Awake`、`Start` | インスタンスを初期化し、最初のオブジェクトとリソースを登録する。 |
| `SystemUpdate` | ロジック周期でゲーム入力を読み、状態を更新する。 |
| `Up` | フレームに応じた表示を更新する。`Update`という別名も使えるが、両方を書いて2回呼ばれることを期待しない。 |
| `End` | 自分のイベント購読を解除し、保持している参照を解放する。 |

コンポーネントの`scene`と`gameObject`から現在のコンテキストを使います。前のシーンのオブジェクト参照を、同名シーンへ再入場した後も新しいインスタンスのものとして使わないでください。

すべてのオブジェクトがUIを持つわけではないため、UIアクセサーはnull許容です。HelloSceneでは対応するUIを作った直後だけ`!`を使っています。存在しない可能性のある既存オブジェクトやコンポーネントを検索する場合は、`null`を確認してください。

インスペクターで値を変更するには、`public float MoveSpeed = 4;`のような対応するインスタンスフィールドを宣言します。`static`、`const`、`readonly`、プロパティは編集フィールドではありません。保存値は初期化前に適用されます。実行中の既存インスタンスへ変更が即時反映されるとは限りません。

## 毎フレーム同じ準備をしない

初期UIは`Start`で作り、文字は値が変わったときだけ更新します。1分ごとの時計を毎ロジック周期に再設定しても表示は滑らかになりません。ファイル読み込み、記録分析、外部エンコードをフレームコールバックへ入れないでください。非同期APIの結果と例外を処理し、ゲームコールバック内で`.Wait()`や`.Result`を使わずに完了を確認します。

処理予算が区切れるのはコールバック間であり、実行中の`Start`を途中で中断できるわけではありません。重いユーザー処理は上限のある小さなステップに分けます。Manager、シーンオブジェクト、GPUへの操作を単に`Task.Run`で包まないでください。バックグラウンドスレッドでも、シーン状態を同時に変更してよいとは限りません。

## ネイティブC++コンポーネント

エンジンのネイティブコンポーネント作成手順と生成された`Sousei.hpp` SDKを使い、非公開の内部ヘッダーには依存しないでください。各開発機で、インストール済みVisual Studio C++ツールセットとWindows SDKを検索または選択します。他の端末の絶対パスはそのまま使えません。

失敗時は、最初のコンパイラーエラー、選択したツールチェーン、ビルドログをまとめて確認します。Visual Studioを開くだけで増分ビルドになるわけではなく、設定したコンパイラー、入力の変更、再利用可能なビルド結果が関係します。下位SDK手順は[文書アーカイブ](https://github.com/koukido/Sousei-Fantasia-Editor-Releases/releases/download/v1.0.31/Sousei-Fantasia-Docs-1.0.31.zip)の`CPP_COMPONENTS.md`にあります。これは旧来の参照資料であり、本ガイドの翻訳チュートリアルではありません。

コード変更後は、コンパイル成功と実行時の初期化成功を分けて確認してください。
