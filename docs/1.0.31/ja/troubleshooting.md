# プロジェクトの問題を調べる

[ガイド一覧](README.md) · [English](../en/troubleshooting.md) · [简体中文](../zh-CN/troubleshooting.md)

シーンを何度も読み直す前に、失敗した操作と最初のエラーを確認します。同じ実行のバージョン、プロジェクトパス、シーンパス、操作、ログをまとめてください。

| 症状 | 最初に確認すること | 次の操作 |
| --- | --- | --- |
| テストが起動せずビルドログのパスが出る | ログの最初のコンパイラーエラー。 | 対象ファイル・行や不足したツールチェーンを直す。一般的な起動ダイアログだけでは原因のコードは分からない。 |
| 2つ目のエディターで開けない | 同じプロジェクトが既に開いていないか。 | 元のインスタンスを通常終了する。活動中のロックを削除して同時書込みを強制しない。 |
| Arenaが準備中のまま | `State`、`Current_Work`、待機・失敗コンポーネント、`Error`。 | パスを調べ、初期化で最初の画面を登録する。Readyを強制しない。 |
| Enterに反応しない | フォーカス、`Can_Activate`、今回のチケット。 | Ready後にもう一度押し、アクティブ化要求が拒否されていないか調べる。 |
| 階層は変わるが映像がない | カメラ連動、方向、描画の停止状態。 | ゲームとエディターを別々に比較し、独自のエディター連携を調べる。 |
| 地図の後からラベルやボタンが出る | UIの遅延登録や無効化された`UI_Text`。 | 非アクティブなUpdateに頼らず、表示前に最初のUIを準備する。 |
| Menuへ戻ったが覆われたまま | 古いチケット・インスタンスとプロジェクトの遮蔽状態。 | 今回の操作とインスタンスを対応付け、自分の終了済み演出だけを解除する。 |
| 録画がFailed、または部分映像しかない | `recording.json`と`encoder.log`。 | 実行資料全体を残し、FFmpeg、容量・時間制限、初フレーム待機、積み残しを調べて再収集する。 |
| CPUトラックの多くが空 | 記録範囲の欠落、完全記録の件数、クロックの対応。 | 全セグメントを読み、プレビュー破棄と実際の記録欠落を区別する。 |
| 開発時のパスでしかゲームが動かない | 相対依存パスと出力フォルダー全体。 | 完全なパッケージを移動し、エディターなしで再現する。 |

## 調査できる問題報告を作る

可能なら小さなプロジェクトへ絞り、行った操作、期待した結果、実際の結果を書きます。エディターのバージョン、言語、グラフィックスAPI、出力サイズ、最初の関連エラーを添えてください。停止の調査には短い映像と、その時間を含むCPU区間が役立ちます。

共有前に認証情報、個人情報、無関係なファイルを取り除きます。実行資料にはゲーム映像、制御信号、パス、ソース名が含まれます。収集やビューアーが自動送信することはなく、共有するかは利用者が決めます。公開の問題報告のために、非公開ゲームやエンジン実装を公開する必要はありません。

新規プロジェクトで動く例が、あるコンポーネントの追加後にだけ失敗するなら、そのリソースとライフサイクルの前提を調べます。最小例でも失敗するなら、再現できるエンジンの問題として保持します。見えている問題をすべてプロジェクト開発者の責任にせず、再現結果で切り分けます。
