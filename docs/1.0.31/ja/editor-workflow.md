# エディターでシーンを確認する

[ガイド一覧](README.md) · [English](../en/editor-workflow.md) · [简体中文](../zh-CN/editor-workflow.md)

リソース管理でファイルを、階層でシーンのオブジェクトを、オブジェクト詳細で選択中のコンポーネントを扱います。複数のオブジェクトが同じリソースを参照できます。オブジェクトの削除とリソースファイルの削除は別の操作です。

## Scene Labを確認する

1. `Menu.sfscene`を開き、階層で`Controller`を選びます。`HelloScene.cs`が追加され、有効になっていることを確認します。
2. テストを実行し、実行時に作成されたオブジェクトを確認します。
3. 描画ワークスペースをゲーム編集とUI編集で切り替えます。UI編集ではキャンバスの選択や整列の操作が使えますが、実行中のゲームを別のシーンに切り替える操作ではありません。
4. 別の保存済みシーンを編集する前にテストを停止します。停止時には編集データに戻り、シミュレーション結果が自動でシーンへ保存されるわけではありません。

## 観察するカメラを選ぶ

エディターカメラとゲームカメラは別です。ゲームカメラとの連動を無効にしている場合、エディターカメラの移動は観察方向だけを変えます。連動を有効にすると、現在のゲームカメラの構図を確認できます。同じシーン名でも、カメラの方向が違えば映像は一致しません。

ドッキングした描画パネルとゲームウィンドウには、それぞれのサイズがあります。パネルのサイズ変更はエディタービューポートに対する操作です。プロジェクトでは`1280 × 720`などのUI基準サイズを使い、実際の出力に合わせて配置できます。サイズの違うスクリーンショットの座標を、そのままポインター判定に使わないでください。

## シーン変更を確認する

[シーンの読み込み](scenes.md)を終えたらArenaへ入り、ゲームとエディターを見比べます。階層は実行中のシーンに追従し、ゲーム/UI編集モードは選択したままになります。階層が変わっているのに映像が空なら、カメラ連動、選択カメラ、描画の停止状態を別々に調べます。同じシーンを繰り返し読み直す必要はありません。

プロジェクトのスクリプトもエディターの観察動作を変えられます。独自のエディター連携コードがある場合、プレビューを停止したりワークスペースを強制変更したりしていないか確認してください。
