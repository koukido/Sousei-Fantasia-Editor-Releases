# ゲームを書き出す

[ガイド一覧](README.md) · [English](../en/exporting.md) · [简体中文](../zh-CN/exporting.md)

Scene Labをエディターなしで起動するゲームにします。書き出しでは同梱の事前ビルド済みGameRuntimeを使い、プロジェクトのコンポーネントをコンパイルします。プレイヤーの端末で非公開エンジンソースをビルドする方式ではありません。

## 準備して書き出す

1. Menu、Arena、コンポーネントの割当て、プロジェクト設定を保存し、起動シーンを確認します。
2. スクリプト内のパスでしか参照されないArenaも含め、両シーンを実行時に使えるようにします。モデル、テクスチャ、フォント、シェーダーの依存を確認し、エディターキャッシュに表示されたことだけで同梱済みと判断しないでください。
3. テストを停止し、プロジェクトメニューからエクスポートを開きます。Windows x64、構成、プロジェクトが対応するグラフィックスAPIを選びます。
4. 出力先はエンジンのインストール先とソースプロジェクトのデータフォルダーの外にします。最初の確認では、起動エラーを読めるようデバッグコンソールを残します。
5. 書き出します。出力先が存在する場合は、上書き、サフィックス付きの別コピー、取消のいずれかを明確に選びます。
6. 出力フォルダー最上位のゲームEXEを起動し、エディターを開かずにMenu → Arenaを試します。

アンチエイリアスは固定の1方式、または実行時切替に必要な対応方式をパッケージに含めます。同梱していない方式を実行時に選ぶことはできません。

## 移動先でも動作を確認する

EXEだけではなく出力フォルダー全体を別のパスへコピーします。エディターを起動せず、シーン、音声、文字、入力、帰還を確認します。パスの変更はパス依存の確認であり、別端末のハードウェア試験を代替するものではありません。

独立した証拠ビューアーとエディターテスト用のウィンドウ枠は、ゲーム内容ではなく開発ツールです。ゲームコードから基本録画APIを利用しても、エディターの収集設定画面や実行資料ライブラリまで埋め込まれるわけではありません。

ソースプロジェクトは別に保管してください。実行パッケージは編集可能なソースのバックアップではなく、新エンジンをその上へコピーする方法もゲームの更新手順ではありません。

失敗した場合は最初のエラーとビルドログを保持し、コンポーネントのコンパイラーや依存関係を直してから再実行します。回避策としてエンジンソース全体をゲームへ入れないでください。
