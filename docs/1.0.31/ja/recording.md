# テストを録画して診断する

[ガイド一覧](README.md) · [English](../en/recording.md) · [简体中文](../zh-CN/recording.md)

録画はプレイヤーが見た映像を確認するために、コンポーネントCPU記録は停止区間と重なった呼び出しを探すために使います。一方で他方を代替することはできません。

## シーン遷移を記録する

1. ゲームのテストを開始し、ツールメニューからゲーム実行資料の収集設定を開きます。
2. 保存先と、`Menu-Arena-return`のような試験内容が分かるラベルを選びます。照合が必要なら映像とCPUを両方有効にします。
3. 映像を記録する場合は、動作する`ffmpeg.exe`を指定します。同梱のメディアデコードDLLはFFmpeg CLIではありません。CPUだけの記録にFFmpegは不要です。
4. ゲーム音声、入力字幕、カーソルを必要に応じて選びます。システムポインターは、対象ゲームがアクティブで、隠れていないクライアント領域内にある場合だけ重ねます。デスクトップ録画ではありません。
5. 収集を開始し、遷移を実行して終了・保存します。`Completed`になってからMP4を完成ファイルとして扱います。設定ウィンドウを閉じるだけでは記録は止まりません。

最初の実ゲームフレームを通常は最大120秒待ちます。待機中に黒画像を生成したり、映像の時間上限を消費したりしません。ゲーム出力のコンテキストが結び付く前のWindowsウィンドウ作成やコンパイルは対象外です。失敗は失敗のままで、`gameplay.partial.mp4`は映像だけの復旧部分であり、完全な音声付き録画ではありません。

[CaptureExample APIサンプル](../examples/CaptureExample.cs)は開始タスクを呼び出し側へ返します。呼び出し側で完了と例外を処理し、ゲームコールバック内で`.Wait()`や`.Result`を使わないでください。`Stop`は非ブロッキングです。ファイルの確定中は`SYSTEM_Game_Recording.Status`を確認します。FFmpegは設定、`SOUSEI_FFMPEG`、PATHから検索できます。

## ビューアーで実行資料を開く

テスト後のゲーム実行資料ライブラリで記録をダブルクリックするか、**Sousei.EvidenceViewer.exe**を単独で開き、フォルダーまたはZIPをドロップします。実行索引、映像、CPUセッション索引、対応する`.profile`フォルダーを一緒に保持してください。`.trace-session.json`だけを移動すると圧縮セグメントが欠けます。

映像とCPUを共通クロックで照合します。対応付けができないという表示がある場合、時間の数字だけで一致と判断しないでください。外部参照がある場合に限って手動オフセットを指定します。

映像が止まった場合は、再生時間が進んでいるのに画面が変わらない区間を選びます。エンジンまたはユーザーコンポーネントのトラックを展開し、呼び出しと未完了区間を調べ、何を待っていたか確認します。古い元画像の取得時刻だけでなく、現在の録画区間を見てください。ロジックが進んでも、映像に同じ画像が繰り返されることがあります。

## 数値を読む

| 表示・フィールド | 意味 |
| --- | --- |
| スレッドID | 処理のレーンであり、ゲーム中のコンポーネント数ではない。 |
| 呼び出し回数 | 選択区間内で保持された計測対象の呼び出し。 |
| 経過時間 | 待機を含む実時間の区間。重複・入れ子を加算してCPU使用率にはできない。 |
| `profiler.stop`の`events`、`dropped` | 互換用の有界プレビュー件数とプレビュー破棄数。 |
| `archiveEvents`、`archiveDroppedEvents`、`archivePath` | 完全記録の件数と場所。欠落を判断する前に確認する。 |

空のトラックには、収集前、欠落、対象範囲外、計測呼び出しの未保持などの可能性があります。コンポーネントが動かなかった証拠ではありません。ビューアーはCPU診断用であり、GPU時間やVRAMの計測器ではありません。

別ワーカーでも記録自体の負荷はあります。性能比較では設定、素材、対象操作をそろえ、最速の1フレームだけでなく複数回の実行を見ます。
